# uv 常用命令大全

> 适用场景：用 uv 管理 Python 版本、项目虚拟环境和依赖。以下命令以 Nanobot 项目为例。

## 先理解三个概念

- **Python 解释器**：运行 Python 代码的程序，例如 Python 3.11。
- **虚拟环境 `.venv`**：某一个项目专用的 Python 和依赖，不会污染系统 Python 或其他项目。
- **项目依赖**：项目运行所需的第三方库。Nanobot 的依赖清单写在 `pyproject.toml`。

## 安装与检查

| 命令 | 用途 | 示例 |
| --- | --- | --- |
| `brew install uv` | 在 macOS 用 Homebrew 安装 uv。 | 第一次安装 uv 时执行一次。 |
| `uv --version` | 查看 uv 是否可用及其版本。 | `uv --version` |
| `uv help` | 打开 uv 的总帮助。 | 不确定命令时先运行它。 |
| `uv help sync` | 查看某个子命令的详细说明。 | 想了解同步依赖的选项时使用。 |

## 管理 Python 版本

| 命令 | 用途 | 示例 |
| --- | --- | --- |
| `uv python list` | 列出可供 uv 使用的 Python 版本。 | `uv python list` |
| `uv python install 3.11` | 下载并安装 Python 3.11，不改动 macOS 自带 Python。 | Nanobot 教学分支要求 Python 3.11+。 |
| `uv python find 3.11` | 找到 uv 将使用的 Python 3.11 路径。 | 排查“到底用了哪个 Python”时使用。 |
| `uv python uninstall 3.11` | 删除由 uv 管理的某个 Python 版本。 | 确定不再有项目使用该版本时再执行。 |

示例：为 Nanobot 准备正确的 Python：

```bash
cd /Users/qzh/AI-Agent/nanobot
uv python install 3.11
uv python find 3.11
```

## 创建和使用虚拟环境

| 命令 | 用途 | 示例 |
| --- | --- | --- |
| `uv venv` | 在当前目录创建 `.venv`。 | 适用于没有 `pyproject.toml` 的小脚本目录。 |
| `uv venv --python 3.11` | 指定 Python 3.11 创建 `.venv`。 | `uv venv --python 3.11` |
| `source .venv/bin/activate` | 在 zsh/bash 中激活虚拟环境。 | 激活后终端提示符会出现 `(.venv)`。 |
| `deactivate` | 退出当前虚拟环境。 | 不再操作该项目时执行。 |

激活后可检查当前 Python：

```bash
source .venv/bin/activate
python --version
which python
```

> 在 Windows PowerShell 中，激活命令是 `.venv\Scripts\Activate.ps1`，不是 `source ...`。

## 同步项目依赖（最常用）

如果目录里有 `pyproject.toml`，优先用 `uv sync`，不要手工逐个 `pip install`。

| 命令 | 用途 | 示例 |
| --- | --- | --- |
| `uv sync` | 创建/更新 `.venv`，安装默认依赖。 | 普通运行项目。 |
| `uv sync --extra dev` | 同时安装名为 `dev` 的可选开发依赖。 | Nanobot：安装 pytest、ruff 等。 |
| `uv sync --all-extras` | 安装所有可选功能依赖。 | 需要测试所有渠道或可选服务时使用。 |
| `uv sync --upgrade` | 重新解析并升级允许升级的依赖。 | 需要升级前先提交或备份代码。 |
| `uv lock` | 生成或更新 `uv.lock`。 | 修改依赖定义后使用。 |
| `uv lock --upgrade` | 重新解析锁定文件并升级依赖。 | 团队统一升级依赖时使用。 |

Nanobot 的推荐初始化：

```bash
cd /Users/qzh/AI-Agent/nanobot
uv python install 3.11
uv sync --extra dev
```

`uv sync` 会根据 `pyproject.toml` 创建 `.venv`；如果产生 `uv.lock`，它会记录准确依赖版本，方便在另一台电脑复现同一环境。

## 运行项目和工具

`uv run` 会确保命令在项目环境中运行，通常不必手动激活 `.venv`。

| 命令 | 用途 | 示例 |
| --- | --- | --- |
| `uv run python main.py` | 用项目环境执行 Python 脚本。 | `uv run python demo.py` |
| `uv run pytest` | 用项目环境运行测试。 | `uv run pytest tests/` |
| `uv run ruff check .` | 用项目环境做静态检查。 | 修改代码后检查。 |
| `uv run nanobot --help` | 运行项目安装的 Nanobot 命令。 | 验证安装。 |

示例：不激活环境也能检查 Nanobot：

```bash
cd /Users/qzh/AI-Agent/nanobot
uv run nanobot --version
uv run pytest
```

## 添加、删除和升级依赖

这些命令适合你自己新建的 uv 项目；阅读 Nanobot 源码时一般不需要修改其依赖。

| 命令 | 用途 | 示例 |
| --- | --- | --- |
| `uv add httpx` | 添加运行依赖，并更新项目配置和锁定文件。 | 为项目增加 HTTP 客户端。 |
| `uv add --dev pytest` | 添加开发依赖。 | 为自己的项目增加测试框架。 |
| `uv remove httpx` | 删除一个依赖。 | 不再使用该库时。 |
| `uv tree` | 以树形结构显示已安装依赖。 | 排查某个库由谁引入。 |
| `uv pip list` | 列出当前环境中的包。 | 类似 `pip list`。 |
| `uv pip show openai` | 查看某个包的版本、位置和依赖。 | 排查 OpenAI SDK 安装情况。 |

示例：创建自己的练习项目并加一个测试依赖：

```bash
mkdir hello-uv
cd hello-uv
uv init
uv add --dev pytest
uv run pytest
```

## 临时安装或运行命令行工具

| 命令 | 用途 | 示例 |
| --- | --- | --- |
| `uv tool install ruff` | 把工具安装到独立、全局可用的环境。 | 长期使用 Ruff。 |
| `uv tool run ruff check .` | 临时下载并运行工具，不长期安装。 | 偶尔检查一个项目。 |
| `uvx ruff check .` | `uv tool run` 的简写。 | 快速运行一次 Ruff。 |
| `uv tool list` | 查看已安装的工具。 | 清点全局 uv 工具。 |
| `uv tool uninstall ruff` | 卸载一个 uv 工具。 | 不再使用时。 |

> `uv tool install nanobot-ai` 会安装 PyPI 上的最新版 Nanobot。学习本仓库的历史教学分支时，应使用 `uv sync --extra dev`，不要用这条命令替代源码环境。

## 常见排查命令

```bash
# 确认你所在目录是否为项目根目录
pwd
ls pyproject.toml

# 查看正在使用的 Python 与 pip
which python
python --version
uv pip list

# 删除后重新生成项目环境（会删除已安装的依赖）
rm -rf .venv
uv sync --extra dev
```

最后两行会删除当前项目的虚拟环境；只有环境损坏或需要彻底重装依赖时才使用。删除 `.venv` 不会删除源代码、Git 提交或 `pyproject.toml`。

## Nanobot 学习时最常用的四条

```bash
cd /Users/qzh/AI-Agent/nanobot
uv sync --extra dev
uv run nanobot --help
uv run pytest
```
